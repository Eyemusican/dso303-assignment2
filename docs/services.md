# Service Documentation

| Service | Role | Why over an alternative | Configuration | Connects to |
|---|---|---|---|---|
| Amazon VPC | Private network for the whole platform | A custom VPC lets me separate public, app and database tiers, which the default VPC does not | 10.0.0.0/16 across 2 AZs. Public subnets 10.0.0.0/19, 10.0.32.0/19. Private app subnets 10.0.64.0/19, 10.0.96.0/19. Private DB subnets 10.0.128.0/19, 10.0.160.0/19. Two /19 blocks left spare for growth. One NAT Gateway per AZ | All services inside it (ALB, ECS, RDS, Lambda) |
| Security groups | Firewall rules between tiers | Security groups are stateful and can reference other groups, so rules stay simple compared to NACLs | ALB SG allows 443 only from the CloudFront prefix list. ECS SG allows 8080 only from ALB SG. RDS SG allows 5432 only from ECS SG and Lambda SG | ALB, ECS, RDS, Lambda |
| Amazon Route 53 | DNS for the exam site | Alias records point straight to CloudFront at no query cost, which an external DNS provider cannot do | Public hosted zone, A alias record for the exam domain to CloudFront | CloudFront |
| AWS WAF | Blocks bad traffic before it reaches the app | Managed rules block common attacks (SQL injection, XSS) without me writing rules, unlike only using security groups which cannot inspect HTTP | Web ACL on CloudFront with AWS managed common rule set and a rate based rule. Campus IP range excluded from the rate rule since many students share one campus IP | CloudFront |
| Amazon CloudFront | CDN for the frontend and entry point for the API | Serves the frontend from edge caches so the 3,000 student peak does not hit the servers, unlike serving files from the ALB | Two origins: S3 frontend bucket (Origin Access Control) and ALB for /api/*. HTTPS only, API paths not cached | Route 53, WAF, S3, ALB, ACM |
| AWS Certificate Manager | TLS certificates for HTTPS | Free public certificates that renew automatically, unlike buying and renewing certificates by hand | Certificate in us-east-1 for CloudFront and one in the main region for the ALB | CloudFront, ALB |
| Amazon S3 (frontend) | Hosts the static web app | Cheaper and simpler than running a web server on EC2, and scales without any setup | Private bucket, Block Public Access on, only CloudFront can read it through OAC | CloudFront |
| Amazon Cognito | Role based sign in for students, tutors and admins | Managed user pool handles passwords, tokens and MFA, so I do not store passwords in my own database | User pool with groups student, tutor and admin. API checks the JWT and group on every request | Frontend, ECS API |
| Application Load Balancer | Spreads API traffic across both AZs | Supports path routing and HTTP health checks, which a Network Load Balancer does not | In both public subnets, HTTPS listener on 443, target group of ECS tasks, health check on /health | CloudFront, ECS, ACM |
| Amazon ECS on Fargate | Runs the API (start exam, autosave, submit, upload URLs) | No servers to patch unlike EC2, and keeps a steady pool of DB connections unlike Lambda at a 3,000 user burst | Service in both private app subnets, minimum 4 tasks (2 per AZ), target tracking at 60% CPU, scheduled scaling to 20 tasks 30 minutes before each exam | ALB, ECR, RDS, S3, SQS, Secrets Manager, CloudWatch |
| Amazon ECR | Stores the API Docker images | Private and works with IAM in the same region, unlike Docker Hub which has pull rate limits | Private repository, scan on push enabled | GitHub Actions, ECS |
| Amazon RDS PostgreSQL (Multi-AZ) | Stores users, exams, questions, answers and marks | Exam data is relational (exams, questions, students, marks), which fits SQL better than DynamoDB. Multi-AZ gives a standby in the second AZ, unlike Single-AZ | Multi-AZ, private DB subnets, storage encrypted with KMS, automated backups kept 35 days (logs saved every 5 minutes for point in time restore), deletion protection on | ECS, Lambda, Secrets Manager, KMS, AWS Backup |
| Amazon S3 (assignments) | Stores assignment files | Cheaper and more durable than EBS. Presigned URLs keep 50 MB uploads off the API | Private bucket, SSE-KMS, versioning on. Presigned POST limited to 50 MB. Lifecycle: Standard-IA after 30 days, Glacier after 1 year, delete after 5 years. Event notification to SQS on new upload | ECS, SQS, KMS, IAM |
| Amazon SQS | Queues marking and email jobs | Holds jobs during the peak so the API stays fast, and retries failed jobs, unlike calling workers directly | Standard queues for marking and notifications, each with a dead letter queue after 3 failed tries | ECS, S3, Lambda |
| AWS Lambda | Workers that auto mark MCQs and send emails | Only runs when there are jobs and scales with queue size, unlike extra ECS tasks running all the time | Two functions triggered by SQS, running in private app subnets to reach RDS | SQS, RDS, SES, CloudWatch |
| Amazon SES | Sends result emails and tutor notifications | Sends to any address from our own domain, unlike SNS email which needs every user to confirm a subscription first | Verified university domain, production access requested | Lambda |
| Amazon CloudWatch | Logs, metrics and alarms | Built into every AWS service, unlike running my own Prometheus and Grafana | Logs from ECS and Lambda. Alarms on ALB 5xx errors, response time, RDS CPU and SQS message age | ECS, Lambda, ALB, RDS, SQS |
| AWS Secrets Manager | Stores the database password | Has built in rotation for RDS, unlike putting the password in code or environment files | RDS credentials secret, rotation every 30 days, read by ECS and Lambda at start | ECS, Lambda, RDS |
| AWS KMS | Encryption keys for data at rest | A customer managed key gives me control and an audit trail of key use, unlike the default AWS owned keys | One customer managed key used by S3, RDS, Secrets Manager and AWS Backup | S3, RDS, Secrets Manager, AWS Backup |
| AWS IAM | Permissions for every service | Roles give short lived credentials, unlike long term access keys that can leak | Least privilege roles for ECS tasks, each Lambda and GitHub Actions (OIDC, no stored keys) | All services |
| AWS Backup | Keeps records for 5 years | RDS automated backups only last 35 days, so they cannot meet the 5 year rule alone | Daily RDS backup plan kept 1825 days in an encrypted backup vault | RDS, KMS |
| GitHub Actions | CI/CD pipeline | My code is already on GitHub, so it needs less setup than CodePipeline and CodeBuild | On push to main: build image, push to ECR, run Terraform, update ECS service | ECR, ECS, Terraform, IAM |
| Terraform | Infrastructure as code | Shows a plan before changing anything and can rebuild or destroy everything with one command, unlike clicking in the console | All infrastructure in infra/, state stored in an S3 bucket | GitHub Actions, all AWS services |
