# Service Documentation

| Service | Role | Why over an alternative | Configuration | Connects to |
|---|---|---|---|---|
| Amazon VPC | The private network for the whole platform | I used my own VPC instead of the default one so I could split it into public, app and database tiers | 10.0.0.0/16 across 2 AZs. Public subnets 10.0.0.0/19, 10.0.32.0/19. Private app subnets 10.0.64.0/19, 10.0.96.0/19. Private DB subnets 10.0.128.0/19, 10.0.160.0/19. Two /19 blocks left spare for growth. One NAT Gateway in each AZ | ALB, ECS, RDS, Lambda |
| Security groups | Firewall rules between the tiers | I chose security groups over NACLs because they are stateful and can point to other groups, so the rules stay short | ALB group allows 443 only from the CloudFront prefix list. ECS group allows 8080 only from the ALB group. RDS group allows 5432 only from the ECS and Lambda groups | ALB, ECS, RDS, Lambda |
| Amazon Route 53 | DNS for the exam site | I used Route 53 because its alias records can point straight to CloudFront and those lookups are free, which an outside DNS provider cannot do | Public hosted zone with an A alias record from the exam domain to CloudFront | CloudFront |
| AWS WAF | Blocks bad traffic before it reaches the app | Security groups cannot look inside HTTP requests, so I added WAF with managed rules to stop things like SQL injection and XSS | Web ACL on CloudFront with the AWS common rule set and a rate limit rule. I left the campus IP range out of the rate limit since lots of students share one campus IP | CloudFront |
| Amazon CloudFront | CDN for the frontend and the entry point for the API | I put the frontend behind CloudFront so the 3,000 student peak is served from edge caches instead of hitting my servers | Two origins: the S3 frontend bucket through Origin Access Control, and the ALB for /api/*. HTTPS only, and API paths are never cached | Route 53, WAF, S3, ALB, ACM |
| AWS Certificate Manager | TLS certificates for HTTPS | ACM gives free public certificates that renew on their own, so I do not have to buy or renew them by hand | One certificate in us-east-1 for CloudFront and one in the main region for the ALB | CloudFront, ALB |
| Amazon S3 (frontend) | Hosts the static web app | Hosting static files in S3 is cheaper and simpler than running a web server on EC2, and it scales without any setup | Private bucket with Block Public Access on. Only CloudFront can read it, through OAC | CloudFront |
| Amazon Cognito | Sign in for students, tutors and admins with their roles | Cognito handles passwords, tokens and MFA for me, so I never store passwords in my own database | User pool with student, tutor and admin groups. The API checks the JWT and the group on every request | Frontend, ECS API |
| Application Load Balancer | Spreads API traffic across both AZs | I picked an ALB over a Network Load Balancer because it supports path routing and HTTP health checks | Sits in both public subnets with an HTTPS listener on 443, a target group of ECS tasks and a health check on /health | CloudFront, ECS, ACM |
| Amazon ECS on Fargate | Runs the API (start exam, autosave, submit, upload links) | With Fargate there are no servers to patch like EC2, and the tasks keep a steady pool of DB connections, which Lambda struggles with when 3,000 students arrive at once | Service in both private app subnets, at least 4 tasks (2 per AZ), target tracking at 60% CPU, and scheduled scaling up to 20 tasks 30 minutes before each exam | ALB, ECR, RDS, S3, SQS, Secrets Manager, CloudWatch |
| Amazon ECR | Stores the API Docker images | ECR is private and works with IAM in the same region, while Docker Hub has pull rate limits | Private repository with scan on push turned on | GitHub Actions, ECS |
| Amazon RDS PostgreSQL (Multi-AZ) | Stores users, exams, questions, answers and marks | Exam data is relational (exams, questions, students, marks), so SQL fits it better than DynamoDB. I used Multi-AZ instead of Single-AZ so there is always a standby in the second AZ | Multi-AZ in the private DB subnets, storage encrypted with KMS, automated backups kept for 35 days (logs saved every 5 minutes for point in time restore), deletion protection on | ECS, Lambda, Secrets Manager, KMS, AWS Backup |
| Amazon S3 (assignments) | Stores the assignment files | S3 is cheaper and more durable than EBS. Presigned URLs keep the 50 MB uploads off the API | Private bucket, SSE-KMS, versioning on. Presigned POST limited to 50 MB. Lifecycle moves files to Standard-IA after 30 days and Glacier after 1 year, and deletes them after 5 years. Sends an event to SQS for every new upload | ECS, SQS, KMS, IAM |
| Amazon SQS | Queues the marking and email jobs | If the API called the workers directly it would slow down at peak. SQS holds the jobs so the API stays fast, and it retries any job that fails | Standard queues for marking and notifications, each with a dead letter queue after 3 failed tries | ECS, S3, Lambda |
| AWS Lambda | Workers that auto mark MCQs and send emails | Lambda only runs when there are jobs and scales with the queue, so I do not pay for extra ECS tasks sitting idle | Two functions triggered by SQS, running in the private app subnets so they can reach RDS | SQS, RDS, SES, CloudWatch |
| Amazon SES | Sends result emails and tutor notifications | SES can send to any address from our own domain, while SNS email makes every user confirm a subscription first | Verified university domain with production access requested | Lambda |
| Amazon CloudWatch | Logs, metrics and alarms | It is built into every AWS service, so I do not have to run my own Prometheus and Grafana | Logs from ECS and Lambda. Alarms on ALB 5xx errors, response time, RDS CPU and SQS message age | ECS, Lambda, ALB, RDS, SQS |
| AWS Secrets Manager | Stores the database password | It can rotate the RDS password by itself, which is safer than keeping the password in code or env files | RDS credentials secret, rotated every 30 days, read by ECS and Lambda when they start | ECS, Lambda, RDS |
| AWS KMS | Encryption keys for data at rest | A customer managed key gives me control and a record of every time the key is used, which the default AWS owned keys do not | One customer managed key used by S3, RDS, Secrets Manager and AWS Backup | S3, RDS, Secrets Manager, AWS Backup |
| AWS IAM | Permissions for every service | Roles give short lived credentials, while long term access keys can leak | Least privilege roles for the ECS tasks, each Lambda and GitHub Actions (OIDC, so no keys are stored) | All services |
| AWS Backup | Keeps the records for 5 years | RDS automated backups only last 35 days, so on their own they cannot meet the 5 year rule | Daily RDS backup plan kept for 1825 days in an encrypted backup vault | RDS, KMS |
| GitHub Actions | CI/CD pipeline | My code is already on GitHub, so this needs less setup than CodePipeline and CodeBuild | On every push to main it builds the image, pushes it to ECR, runs Terraform and updates the ECS service | ECR, ECS, Terraform, IAM |
| Terraform | Infrastructure as code | Terraform shows me a plan before it changes anything and can build or destroy everything with one command, which clicking in the console cannot do | All infrastructure lives in infra/ and the state is stored in an S3 bucket | GitHub Actions, all AWS services |
